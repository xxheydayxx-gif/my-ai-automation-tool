# Dev_03. 데이터 모델, 상태 워크플로우, 감사 로그

## 목표

계약 1건의 생성부터 종료까지 추적 가능한 데이터 모델과 상태 전환 규칙을 구현한다.

## 구현 범위

- 핵심 엔터티 모델
- 계약 상태 모델
- 조건부 상태 생성
- 상태 변경 로그
- 감사 로그 공통 미들웨어
- 샘플 DB 또는 로컬 저장소

## 개발 지시

1. 최소 엔터티를 구현한다.
   - User, Role, Department
   - ContractCase, ContractVersion
   - Checklist, ChecklistItem
   - Document, DocumentTemplate
   - Regulation, RegulationClause
   - Rule, RuleExecution
   - ReviewTicket, Comment
   - Notification, AuditLog
2. 계약 기본 상태는 명세서의 상태 코드를 따른다.
3. 허용된 이전·다음 상태만 전환 가능하게 한다.
4. 필수 서류, 승인, 검토가 누락되면 다음 상태 이동을 차단한다.
5. 개인정보, 보안, 일상감사 조건에 따라 조건부 상태를 생성할 수 있게 한다.
6. 조회, 생성, 수정, 삭제, 다운로드, 승인, 판정 실행은 감사 로그를 남긴다.
7. 로그는 사용자, 행동, 대상, 이전값, 이후값, 사유, 시각, trace id를 포함한다.

## UI 개발 지시

- 계약 상세 화면에 상태 타임라인을 표시한다.
- 현재 상태, 다음 가능 상태, 차단 사유를 명확히 보여준다.
- 상태 변경 버튼은 권한과 조건을 만족할 때만 활성화한다.
- 감사 로그 탭은 필터와 검색을 제공한다.
- 모바일에서는 상태 타임라인을 세로형으로 표시한다.

## 완료 조건

- 계약 생성 시 기본 상태가 저장된다.
- 잘못된 상태 전환이 차단된다.
- 상태 변경마다 로그가 남는다.
- 조건부 검토 상태가 자동 생성된다.
- 감사 로그를 화면에서 확인할 수 있다.
