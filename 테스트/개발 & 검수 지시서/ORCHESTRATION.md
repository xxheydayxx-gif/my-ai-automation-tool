# 계약AX Desk 오케스트레이션 구조

## 목적

개발 지시서와 검수 지시서를 단순 문서가 아니라 실행 가능한 단계형 프로세스로 연결한다. 오케스트레이터는 개발 에이전트와 검수 에이전트를 순차적으로 호출하여 구현, 검수, 수정, 보고를 반복한다.

## 역할 구성

| 역할 | 책임 |
|---|---|
| 오케스트레이터 | 전체 단계 순서 관리, 산출물 확인, 실패 항목 재작업 지시, 완료 보고 |
| 개발 에이전트 | Dev 문서 기반 구현, UI·상태·데이터·상호작용 개발 |
| 검수 에이전트 | Chk 문서 기반 검수, 이슈 등급화, 재검수 |
| 사용자 승인자 | 최종 결과 확인, 운영 범위 확정 |

## 실행 흐름

```text
요구사항 확인
  ↓
Dev_N 단계 구현
  ↓
Chk_N 단계 검수
  ↓
실패 항목 존재?
  ├─ 예: 개발 에이전트 수정 → Chk_N 재검수
  └─ 아니오: 다음 단계 진행
  ↓
전체 단계 완료
  ↓
통합 검수
  ↓
완성 완료 보고서 작성
```

## 단계 게이트

| 게이트 | 통과 조건 |
|---|---|
| G1 기반 | 로컬 서버 실행, 주요 라우팅, 반응형 레이아웃 |
| G2 권한 | 역할별 메뉴·데이터 분리, 직접 URL 차단 |
| G3 계약 준비 | 계약 생성, 자동 저장, 동적 질문 |
| G4 규칙·근거 | 규칙 판정, 근거 조항, 검토 필요 전환 |
| G5 검토 | 검토함, 보완 요청, 승인, 감사 로그 |
| G6 운영 | 관리자 콘솔, 회귀 테스트, 배포·롤백 UI |
| G7 확장 | 체결, 이행, 검사, 지급, 하자, 감사 리포트 |
| G8 완료 | 검수 결과 보고서와 실행 URL 제공 |

## 현재 실행 계획

이번 수행에서는 로컬 실행 가능한 프론트엔드 중심 단일 페이지 애플리케이션으로 구현한다. 실제 SSO, ERP, DMS, AI 모델 연계는 인터페이스와 목업 상태로 구성하되, 사용자는 화면에서 전체 업무 흐름을 클릭해 검증할 수 있어야 한다.
