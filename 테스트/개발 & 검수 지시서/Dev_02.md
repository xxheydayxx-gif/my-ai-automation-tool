# Dev_02. 인증, 조직도, 역할 기반 권한

## 목표

기관 SSO와 조직도 연계를 실제 연계 전에도 검증할 수 있도록 인증·사용자·부서·역할 모델을 구현하고, 역할별 메뉴와 데이터 접근을 제한한다.

## 구현 범위

- 로그인 화면 또는 개발용 사용자 선택 화면
- 사용자, 부서, 역할, 권한 모델
- 역할 기반 메뉴 노출 제어
- 계약 건 조회 권한 필터
- 문서 권한 상속 구조
- 권한 변경 이력 저장

## 개발 지시

1. 개발 환경에서는 사용자 역할을 전환할 수 있는 개발용 로그인 기능을 제공한다.
2. 운영 SSO 연계를 고려하여 인증 인터페이스를 분리한다.
3. 역할별 기본 접근 권한을 정의한다.
   - 사업부서: 본인·소속 부서 계약 생성 및 조회
   - 계약 담당자: 배정 계약 또는 전체 계약 검토
   - 감사 담당자: 감사 대상 계약과 승인 로그 조회
   - 관리자: 규정, 규칙, 서식, 사용자 관리
4. 권한이 없는 메뉴는 숨기고, 직접 URL 접근 시 접근 거부 화면을 표시한다.
5. AI 검색, 문서 열람, 첨부 다운로드에도 동일한 권한 필터를 적용할 수 있도록 service 계층에 권한 체크를 둔다.
6. 관리자 권한 변경 시 변경 전후 값, 변경자, 변경일, 사유를 기록한다.

## UI 개발 지시

- 헤더 우측에 현재 사용자명, 부서, 역할 배지를 표시한다.
- 개발 모드에서는 역할 전환 메뉴를 제공하되 운영 모드에서는 숨길 수 있게 한다.
- 접근 거부 화면은 어떤 권한이 필요한지와 문의 경로를 명확히 보여준다.
- 관리자 사용자 목록은 검색, 부서 필터, 역할 필터, 재직 상태 필터를 제공한다.
- 권한 변경 모달은 변경 사유 입력을 필수로 한다.

## API/데이터 지시

- `GET /api/me`
- `GET /api/users`
- `GET /api/departments`
- `GET /api/roles`
- `POST /api/admin/users/:id/roles`
- `GET /api/audit/permission-changes`

## 완료 조건

- 역할별 메뉴 노출이 다르게 동작한다.
- 권한 없는 계약과 문서는 조회되지 않는다.
- 직접 URL 접근도 차단된다.
- 권한 변경 로그가 남는다.
