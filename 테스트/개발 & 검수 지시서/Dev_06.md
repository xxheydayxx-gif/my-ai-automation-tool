# Dev_06. 규칙 엔진, 규정 레지스트리, 계약 방식 판정

## 목표

계약 방식과 필수 절차를 코드에 고정하지 않고, 시행일과 근거 조항을 가진 규칙 데이터로 판정한다.

## 구현 범위

- 규정 레지스트리
- 조항 단위 규정 데이터
- 규칙 테이블
- 규칙 실행 엔진
- 계약 방식 후보 판정
- 보완 질문 생성
- 담당자 검토 전환
- 규칙 실행 로그

## 개발 지시

1. 규칙은 조건, 결과, 우선순위, 시행일, 종료일, 근거 조항, 승인 상태를 가진다.
2. 규칙 실행 시 현재 계약 조건과 기준일을 입력으로 받는다.
3. 결과는 확정값이 아니라 후보와 근거로 표시한다.
4. 충돌하거나 불확실한 경우 `담당자 검토 필요`로 전환한다.
5. 판정 결과에는 규정명, 조항, 시행일, 규칙 버전을 포함한다.
6. 입력값 변경 전후 판정 비교를 저장한다.
7. 규칙 실행은 단위 테스트와 회귀 테스트가 가능하게 순수 함수 또는 독립 모듈로 분리한다.

## UI 개발 지시

- 계약 방식 후보는 일반경쟁, 제한경쟁, 수의계약 검토 후보를 비교 카드 또는 표로 표시한다.
- 각 후보에는 판단 근거와 추가 확인사항을 함께 보여준다.
- 담당자 검토 필요 상태는 경고색과 명확한 문구로 표시한다.
- 원문 규정 링크 또는 조항 상세 패널을 제공한다.
- 보완 질문은 사용자가 바로 답변할 수 있는 입력 UI로 제공한다.

## 완료 조건

- 규칙 데이터로 계약 방식 후보가 산출된다.
- 근거 없는 판정 결과가 표시되지 않는다.
- 보완 질문과 담당자 검토 전환이 동작한다.
- 규칙 실행 로그가 저장된다.
