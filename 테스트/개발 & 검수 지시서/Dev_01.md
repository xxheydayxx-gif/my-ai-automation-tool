# Dev_01. 프로젝트 기반, 로컬 실행, UI 시스템

## 목표

계약AX Desk를 `localhost`에서 실행 가능한 동적·반응형 웹 애플리케이션으로 구축할 수 있도록 프로젝트 구조, 공통 UI, 라우팅, 목업 데이터, 품질 기준을 먼저 만든다.

## 구현 범위

- 프론트엔드 앱 초기 구성
- 백엔드 또는 API 목업 서버 초기 구성
- 로컬 개발 서버 실행 스크립트
- 반응형 레이아웃, 내비게이션, 공통 컴포넌트
- 디자인 토큰과 접근성 기본값
- 샘플 사용자, 계약, 규정, 알림 데이터

## 개발 지시

1. 웹 앱은 `npm run dev` 또는 이에 준하는 단일 명령으로 실행되게 구성한다.
2. 실행 후 사용자가 `http://localhost:<port>`로 접속할 수 있어야 한다.
3. 초기 라우트는 다음을 포함한다.
   - `/dashboard`
   - `/contracts/new`
   - `/contracts/:id/precheck`
   - `/reviews`
   - `/regulations/search`
   - `/admin`
4. 백엔드가 아직 없더라도 화면 흐름 검증이 가능하도록 API 목업 계층을 둔다.
5. 실제 API 전환이 쉽도록 화면 컴포넌트에서 목업 데이터를 직접 import하지 말고 service 또는 query 계층을 통한다.
6. 공통 에러, 로딩, 빈 상태, 접근 거부 화면을 만든다.

## UI 개발 지시

- 첫 화면은 마케팅 랜딩이 아니라 업무 대시보드로 진입한다.
- 좌측 또는 상단 내비게이션에 주요 메뉴를 배치한다.
- 모바일에서는 내비게이션을 접을 수 있어야 한다.
- 화면은 다음 공통 영역을 가진다.
  - 앱 헤더: 서비스명, 현재 사용자, 알림, 역할 전환
  - 메뉴: 대시보드, 새 계약 준비, 검토함, 규정 검색, 관리자
  - 본문: 업무 화면
  - 상태 표시: 로딩, 저장됨, 오류, 권한 제한
- 버튼, 입력, 테이블, 배지, 탭, 모달, 토스트, 파일 업로드, 날짜 범위 입력을 공통 컴포넌트로 만든다.
- 공공 업무 시스템에 맞게 장식보다 정보 밀도와 명확한 계층을 우선한다.
- 카드 안에 카드를 중첩하지 않는다.

## 데이터 초기값

- 사용자 8종 역할: 사업부서, 계약 담당자, 감사, 재무, 법무, 정보보안, 관리자, 부서장
- 계약 유형 3종: 물품, 일반용역, 정보화용역
- 계약 상태 샘플: 임시저장, 사전점검, 계약부서 검토, 보완 요청, 검토 완료
- 규정 샘플: 법령, 내규, 매뉴얼, 서식
- 알림 샘플: 검토 요청, 보완 요청, 기한 임박, 규정 변경

## 완료 조건

- 로컬 서버가 정상 실행된다.
- 주요 메뉴 이동이 가능하다.
- 데스크톱, 태블릿, 모바일에서 화면이 깨지지 않는다.
- 공통 UI 컴포넌트가 최소 10개 이상 준비된다.
- 목업 데이터로 전체 메뉴가 비어 보이지 않는다.
