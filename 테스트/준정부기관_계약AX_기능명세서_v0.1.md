## 0. 문서 사용 원칙

본 문서는 실제 개발 착수를 위한 기능명세서이다.  
계약 관련 자동화는 담당자의 최종 판단과 승인을 대체하지 않는다.

법령, 시행령, 예규, 고시, 기관 내규의 금액 기준과 적용 조건은 개정될 수 있으므로 소스코드에 직접 고정하지 않는다.  
모든 기준값은 시행일, 종료일, 근거 조항, 승인자를 포함한 규칙 테이블로 관리한다.

### 0.1 법령 기준

준정부기관의 계약 업무는 다음 순서로 규정을 적용한다.

1. 「공기업·준정부기관 계약사무규칙」
2. 위 규칙에서 정하지 않은 사항에 대한 국가계약 관계 법령 준용
3. 계약예규·고시·지침
4. 기관 자체 계약규정
5. 위임전결규정, 일상감사규정, 계약심의 관련 규정
6. 내부 업무 매뉴얼과 서식

### 0.2 법령 검증 주의사항

- 본 문서는 기능 설계를 위한 기준 문서이다.
- 실제 운영 배포 전 최신 법령과 기관 내부 규정을 계약부서, 감사·법무 담당자가 검토해야 한다.
- 자동 판정이 위험한 경우 시스템은 결과를 확정하지 않고 `담당자 검토 필요` 상태로 전환한다.
- 법령 개정은 자동 감지할 수 있으나 운영 반영은 담당자 승인과 회귀 테스트 후 수행한다.

### 0.3 공식 참고 경로

- 국가법령정보센터: https://www.law.go.kr
- 공기업·준정부기관 계약사무규칙: 국가법령정보센터에서 최신 시행본 확인
- 국가를 당사자로 하는 계약에 관한 법률: 국가법령정보센터에서 최신 시행본 확인
- 국가를 당사자로 하는 계약에 관한 법률 시행령: 국가법령정보센터에서 최신 시행본 확인

# 1. 제품 개요

## 1.1 제품 정의

> 사업부서 담당자가 사업명, 계약 유형, 추정가격, 기간, 주요 조건을 입력하면 적용 규정과 내부 절차를 분석하여 계약 추진 경로, 필수 서류, 예상 일정, 위험 요소를 근거와 함께 제시하고, 서식 초안을 생성하며, 체결 이후 검사·대금 지급·하자관리까지 후속 업무를 연결하는 준정부기관용 계약 AX 시스템

## 1.2 해결 과제

| 문제 | 현행 업무의 증상 | 시스템 목표 |
|---|---|---|
| 규정 분산 | 법령, 내규, 예규, 서식이 여러 위치에 분산 | 근거 기반 통합 안내 |
| 반복 문의 | 사업부서가 계약부서에 유사 질문을 반복 | 사전 자가점검 |
| 반복 입력 | 동일 정보를 여러 서식에 재입력 | 공통 필드 자동 반영 |
| 결재 직전 오류 | 금액, 날짜, 첨부 누락을 늦게 발견 | 제출 전 자동 점검 |
| 후속관리 누락 | 납품, 검사, 지급, 보증서 만료일을 수기 관리 | 이벤트 기반 업무 생성 |
| 법령 개정 위험 | 구버전 서식과 오래된 기준 사용 | 시행일 기반 버전 통제 |
| 감사 대응 부담 | 판단 근거와 수정 이력이 분산 | 계약별 감사 패키지 |

## 1.3 제품 원칙

1. 전자입찰·ERP·전자결재 시스템을 대체하지 않는다.
2. 기존 시스템 앞단과 후속관리 사이를 연결하는 업무 레이어로 구현한다.
3. 규칙 엔진과 생성형 AI의 역할을 분리한다.
4. 모든 판정과 답변에 근거 조항, 시행일, 규칙 버전을 표시한다.
5. 자동 판정이 불확실하면 담당자 검토로 전환한다.
6. 사용자가 열람 권한이 없는 문서는 AI도 검색하지 못한다.
7. 계약 1건의 전체 상태 변경 이력을 보존한다.
8. 최초 내부 실증은 물품, 일반용역, 정보화용역으로 제한한다.

# 3. 사용자와 권한

## 3.1 사용자 역할

| 역할 ID | 역할명 | 주요 목적 |
|---|---|---|
| ROLE-BIZ | 사업부서 담당자 | 계약 준비, 서식 작성, 보완, 납품·검사 지원 |
| ROLE-CONTRACT | 계약 담당자 | 사전검토, 계약 방식 검토, 체결, 변경계약 |
| ROLE-AUDIT | 감사 담당자 | 일상감사 대상 확인, 위험 계약 검토 |
| ROLE-FINANCE | 재무·회계 담당자 | 지급 가능 상태 확인, 증빙 점검 |
| ROLE-LEGAL | 법무 담당자 | 자동 판정이 어려운 예외 검토 |
| ROLE-INFOSEC | 정보보안 담당자 | 정보화사업 보안 검토, 데이터 보호 |
| ROLE-ADMIN | 시스템 관리자 | 사용자, 권한, 규정, 규칙, 서식 관리 |
| ROLE-EXEC | 관리자·부서장 | 현황, 지연, 리스크, ROI 대시보드 |

## 3.2 권한 원칙

- 최소 권한 원칙을 적용한다.
- 문서 권한은 원문 시스템 또는 계약 건 권한을 상속한다.
- 계약 담당자는 기관 정책에 따라 전체 계약 또는 배정 계약만 조회한다.
- 사업부서 사용자는 본인 또는 소속 부서가 생성한 계약을 조회한다.
- 감사 담당자는 감사 대상 계약과 승인된 범위의 로그를 조회한다.
- AI 검색 결과도 사용자 권한 필터를 통과한 문서만 포함한다.
- 개인정보와 민감정보 조회는 별도 로그를 남긴다.
- 관리자라도 원문 문서를 무조건 열람할 수 없도록 분리 권한을 제공한다.

## 7.5 답변 정책

- 답변에는 규정명, 조·항·호, 시행일, 원문 링크를 표시한다.
- 출처가 없는 경우 추정 답변을 제공하지 않는다.
- 규정 간 충돌 가능성이 있으면 복수 근거와 `담당자 검토 필요`를 표시한다.
- 폐지된 규정은 기본 검색 결과에서 제외한다.
- 법률적 결론을 단정하지 않고 실무 검토 후보를 제시한다.
- 민감문서는 외부 모델로 전달하지 않는다.
- 모든 질문, 검색 결과, 답변, 피드백을 정책에 따라 로그로 남긴다.

# 27. 결론

가장 먼저 구현해야 할 것은 화려한 AI 챗봇이 아니다.

1. 기관 내부 규정과 서식을 수집한다.
2. 계약 담당자의 판단을 규칙 테이블로 구조화한다.
3. 물품, 일반용역, 정보화용역의 계약 준비 화면을 만든다.
4. 모든 결과에 근거 조항과 시행일을 표시한다.
5. 과거 계약 사례로 회귀 테스트를 수행한다.
6. 서식 자동작성과 문서 오류 점검으로 체감 효과를 만든다.
7. 제한 운영 후 체결, 검사, 지급, 하자관리로 확장한다.

이 순서를 따르면 계약AX Desk는 단순한 안내 페이지가 아니라, 준정부기관의 계약 업무를 지속적으로 연결하는 실무 운영 플랫폼으로 발전할 수 있다.
